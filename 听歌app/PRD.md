# 生活专属 App 产品需求文档（PRD）

## 1. 产品目标与使用场景

### 1.1 产品目标

为个人提供一个在当前电脑浏览器中使用的生活内容管理 App。用户可以在首页快速了解和访问今日推荐歌曲、热门视频、保存路径及过去流行单曲，并在本机管理收藏、路径和偏好设置。

### 1.2 使用场景

- 打开 App 后，在首页快速查看今日推荐歌曲和各模块摘要。
- 浏览公开来源提供的今日热门歌曲、热门视频及历史流行单曲。
- 收藏感兴趣的歌曲或视频，之后可从对应模块继续查看。
- 手动登记常用的本机文件或文件夹路径，并进行整理和查找。
- 备份本机数据，或在需要时从备份恢复。

### 1.3 产品约束

- 第一版只供个人在当前电脑的浏览器中使用。
- 不需要注册或登录，不使用云数据库，不部署手机端。
- 联网仅用于获取公开热门内容；个人收藏、路径、设置及内容缓存保存在当前浏览器本机。
- 外部榜单和内容来源暂不指定平台，优先使用可用的公开来源；不要求登录。来源可用性及其提供的数据范围以实际情况为准。
- 浏览器清理站点数据、使用隐私模式或更换浏览器可能造成本机数据不可用，因此必须提供数据导出与恢复能力。

## 2. 整体页面框架与导航结构

### 2.1 页面框架

- 面向电脑浏览器，采用左侧固定导航栏和右侧页面内容区。
- 当前所在模块在导航栏中有明确的选中状态。
- 页面标题附近显示必要的数据状态和最近更新时间。
- 外部热门内容需标示来源及最近更新时间。
- 各页面应明确呈现加载中、首次无数据、无匹配结果及更新失败等状态；更新失败时提示原因或状态，不得静默显示为空。
- 网络更新失败时保留并显示最近一次成功获取的内容，同时标明该内容的更新时间。

### 2.2 导航结构

左侧导航按以下模块组织：

1. 首页总览
2. 今天的热门歌曲
3. 热门视频
4. 保存路径
5. 过去流行单曲
6. 数据与设置

## 3. 首页内容结构

首页用于总览和快速访问，不替代各模块的完整内容列表。

### 3.1 今日推荐歌曲

- 作为首页视觉重点，展示今日推荐歌曲的核心信息。
- 提供查看歌曲详情、收藏/取消收藏，以及打开可用来源页面的入口。
- 推荐内容来自今日热门歌曲模块中当前可用的歌曲数据；首页与歌曲模块共享歌曲记录和收藏状态。
- 显示来源及数据更新时间；尚无数据或更新失败时显示明确状态。

### 3.2 快速访问

- 提供进入六个主要模块的快捷入口。
- 点击入口后进入对应模块页面。

### 3.3 模块摘要

- 展示热门视频、保存路径、过去流行单曲等模块的简要摘要或数量信息。
- 摘要提供进入对应模块的入口。
- 摘要数据应与相应模块的本机数据或最近成功获取的数据一致。

## 4. 各模块用途、必要数据与操作

### 4.1 今天的热门歌曲

**用途：** 浏览可用公开来源提供的当日热门歌曲，并管理个人收藏。

**第一版必要数据：**

- 歌曲名称、歌手。
- 榜单排名（来源提供时）。
- 来源名称及可打开的来源链接（来源提供时）。
- 最近成功获取时间。
- 本机收藏状态。

**第一版必要操作：**

- 查看歌曲榜单及单曲详情。
- 手动刷新榜单。
- 收藏或取消收藏歌曲。
- 打开歌曲的来源页面。

页面提供独立的 Wikimedia Commons 开放授权音频搜索。用户可搜索实际媒体文件并使用浏览器原生播放器直接播放；页面需展示可获取到的许可证和来源署名链接。QQ 音乐、网易云音乐榜单数据本身不保证提供可播放音频流。

### 4.2 热门视频

**用途：** 浏览可用公开来源提供的热门视频，并管理个人收藏。

**第一版必要数据：**

- 视频标题。
- 发布者（来源提供时）。
- 封面（来源提供且可访问时）。
- 来源名称及可打开的来源链接（来源提供时）。
- 最近成功获取时间。
- 本机收藏状态。

**第一版必要操作：**

- 浏览视频卡片及查看视频信息。
- 手动刷新内容。
- 收藏或取消收藏视频。
- 打开视频的来源页面。
- 在独立的 Wikimedia Commons 开放授权视频搜索中查找媒体文件，并在页面内直接播放；展示可获取到的许可证信息和来源署名链接。

抖音热搜词条仅为话题关键词，并非视频文件；网页内播放需使用开放授权媒体搜索结果。

### 4.3 保存路径

**用途：** 手动登记和整理个人常用的本机文件或文件夹路径。

**第一版必要数据：**

- 路径名称。
- 路径内容。
- 分类或标签（可为空）。
- 备注（可为空）。

**第一版必要操作：**

- 新增、编辑、删除路径记录。
- 按名称或路径搜索，并按分类筛选。
- 复制路径。
- 删除前明确确认。

第一版不扫描本机文件。受浏览器权限限制，不保证能够直接打开或读取任意本机路径。

### 4.4 过去流行单曲

**用途：** 按年份等方式浏览历史流行单曲。

**第一版必要数据：**

- 歌曲名称、歌手。
- 年份（如可获得）。
- 来源及来源链接（如可获得）。
- 本机收藏状态（适用时）。

**第一版必要操作：**

- 按年份筛选和浏览歌曲。
- 查看歌曲信息。
- 收藏或取消收藏（数据支持时）。
- 打开可用的来源页面。

历史数据的年份范围和完整度取决于可获得的可靠公开数据；不虚构缺失信息。

### 4.5 数据与设置

**用途：** 管理本机数据、基础偏好和数据备份。

**第一版必要数据：**

- 基础应用偏好设置，包括首选歌曲来源及界面主题（深蓝科技、浅色、深色）。
- 本机数据存储状态及最近一次备份/导入状态（如适用）。

**第一版必要操作：**

- 切换界面主题，并将选择保存在当前浏览器；主题应统一应用于首页及各功能页面。
- 导出本机数据备份文件。
- 从备份文件导入并恢复数据。
- 导入前校验文件格式和数据；无效备份应说明失败，不得破坏已有数据。
- 恢复前展示影响并要求确认。
- 清空本机数据前二次确认。

### 4.6 首页总览

**用途：** 汇总今日推荐和各模块的重要摘要，作为日常使用入口。

**第一版必要数据：**

- 今日推荐歌曲及其来源、更新时间和收藏状态。
- 各模块可用的摘要信息。

**第一版必要操作：**

- 查看推荐歌曲详情、收藏/取消收藏、打开来源。
- 通过快速入口进入各模块。
- 通过摘要入口进入对应模块。

## 5. 首页、今日歌曲与模块之间的关系

- 首页是模块内容的摘要与导航入口，不建立与模块数据相互独立的副本。
- 首页今日推荐歌曲从“今天的热门歌曲”模块当前可用的数据中选取或展示。
- 在首页或歌曲模块修改歌曲收藏状态，两个页面应保持一致。
- 热门视频、保存路径、过去流行单曲的摘要由各自模块数据生成；进入摘要后应打开对应模块。
- 收藏、路径、设置等个人数据由本机数据层统一保存，模块之间共享同一份记录。
- 数据刷新结果应更新相应模块及首页摘要；刷新失败时使用最近一次成功数据并显示其更新时间和失败状态。

## 6. 本地数据、备份与恢复要求

### 6.1 本机持久化

- 所有个人数据和最近成功获取的内容缓存保存在当前浏览器的本机持久化存储中，不写入云端。
- 具体存储技术可在开发阶段确定，但必须支持结构化数据、刷新后读取和浏览器重启后保留。
- 浏览器重新打开 App 后，收藏、路径、设置和内容缓存仍可读取。
- 浏览器清理站点数据、使用隐私模式或更换浏览器可能导致数据丢失，界面应在数据与设置中说明并提供备份能力。

### 6.2 备份文件

- 用户可将个人数据导出为本机文件。
- 备份至少包含收藏、保存路径、设置及需要保留的本机记录；如包含外部内容缓存，应保存其来源与更新时间。
- 备份文件应包含可用于识别其格式/版本的信息，以便后续校验和兼容处理。
- 导出失败时明确提示，不得显示成功状态。

### 6.3 恢复

- 用户可选择本机备份文件并恢复数据。
- 恢复前校验文件格式、版本及必要字段；无效或不支持的文件应明确报错，且不改变现有数据。
- 恢复前提示将要恢复或替换的数据，并要求用户确认。
- 恢复成功后，相关页面应立即反映恢复的数据。
- 如果恢复采用整体替换，应明确告知用户；第一版不要求跨设备或云端合并。

## 7. 第一版必须完成的功能

1. 提供左侧固定导航及六个模块页面。
2. 首页展示今日推荐歌曲、六个模块的快速入口，以及热门视频、保存路径和过去流行单曲等摘要。
3. 获取可用公开来源的今日热门歌曲和热门视频，并显示来源与更新时间。
4. 提供热门歌曲和视频的手动刷新、详情/信息查看、来源跳转及本机收藏管理。
5. 刷新失败时明确提示，并保留最近一次成功数据。
6. 提供过去流行单曲的年份筛选和浏览；数据不足时如实显示可用范围。
7. 提供保存路径的手动新增、编辑、删除、搜索、分类筛选和复制。
8. 将收藏、路径、设置及必要缓存保存在当前浏览器本机，确保刷新、关闭和重启浏览器后仍可读取。
9. 提供本机数据备份导出和校验后的恢复导入。
10. 对清空数据、删除路径和替换恢复等有数据损失风险的操作提供明确确认。
11. 在加载、无数据、无搜索结果、更新失败和导入失败等情况下提供清晰状态反馈。

## 8. 第一版暂时不做的功能

- 注册、登录、账号体系或云端同步。
- 云数据库、服务器端个人数据存储或手机端部署。
- 自动扫描本机文件、读取任意路径内容或管理本机文件本身。
- 下载或托管歌曲、视频，绕过平台限制，或保证所有外部内容永久可用。
- 不保证任意平台内容均可内嵌播放；仅对搜索到且浏览器支持的 Wikimedia Commons 直接媒体文件提供网页内播放器。
- 指定或保证某一个音乐/视频平台；平台来源以可用的公开数据为准。
- 保证历史单曲数据覆盖特定年份范围或完整度。
- 跨设备合并备份、云端恢复或复杂的数据冲突合并。

## 9. 验收标准

以下检查均可在支持的桌面浏览器中手动执行。涉及联网内容的检查应使用当时可访问的公开来源。

### 9.1 页面与导航

- [ ] 打开 App 后可见左侧固定导航，包含且仅需包含六个已定义模块入口。
- [ ] 点击各导航入口会显示对应模块，当前入口有清晰选中状态。
- [ ] 每个模块有符合其用途的内容与操作，不是仅更换名称的通用任务列表。

### 9.2 首页

- [ ] 首页将今日推荐歌曲作为主要内容展示，并显示可获得的歌曲信息、来源和更新时间。
- [ ] 首页可进入六个模块，并显示热门视频、保存路径、过去流行单曲等摘要入口。
- [ ] 从首页歌曲入口执行收藏/取消收藏后，今日热门歌曲模块中的收藏状态一致。
- [ ] 点击模块摘要或快速入口会进入正确的模块。

### 9.3 今日歌曲与热门视频

- [ ] 今日热门歌曲页展示可获得的歌曲名称、歌手、来源及更新时间；排名在来源提供时展示。
- [ ] 热门视频页展示可获得的标题、来源、发布者和封面。
- [ ] 两个页面均可手动刷新、查看信息、收藏/取消收藏并打开可用来源页面。
- [ ] 歌曲页和热门视频页均提供独立的 Wikimedia Commons 媒体搜索；搜索结果显示来源及可获得的许可证信息，并可通过浏览器原生控件在页面内播放受支持的直接媒体文件。
- [ ] 搜索无结果、网络/API 不可用、媒体格式不受支持或播放失败时，向用户显示明确状态；不得将榜单歌曲或热搜关键词伪装成可播放媒体。
- [ ] 在网络不可用或来源请求失败时，页面明确显示更新失败；若有旧数据，旧数据仍可见且标示其更新时间。
- [ ] 首次加载且没有缓存时，页面显示清晰的无数据/无法获取状态，而非空白或伪造内容。

### 9.4 保存路径与过去流行单曲

- [ ] 保存路径可新增、编辑、搜索、筛选、复制和删除记录；删除需确认。
- [ ] 重新打开页面后，保存路径记录仍存在。
- [ ] 过去流行单曲可按可用年份筛选；数据不可用时如实提示，不显示虚构条目。
- [ ] 历史单曲可查看可用信息，并在来源支持时提供收藏及来源跳转。

### 9.5 本机持久化与备份恢复

- [ ] 收藏、路径和设置在页面刷新后仍存在。
- [ ] 关闭并重新打开浏览器后，收藏、路径和设置仍可读取。
- [ ] 导出操作生成本机备份文件；导出的文件包含已创建的收藏、路径及设置。
- [ ] 用有效备份恢复后，备份中的数据在对应模块可见。
- [ ] 对无效或不支持的备份进行导入时，显示明确错误，原有数据不被更改。
- [ ] 替换恢复和清空数据前均有明确说明及确认步骤。
- [ ] 不登录、不配置云数据库的情况下，核心个人数据功能可用；联网仅影响外部热门内容的获取。

### 9.6 状态反馈

- [ ] 加载中、无数据、无搜索结果、刷新失败、导入失败等状态均有可理解的页面提示。
- [ ] 外部内容均能辨认来源；内容缓存过期或联网刷新失败时能看到最近成功更新时间。
